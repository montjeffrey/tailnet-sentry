The first release of `sentry`: scan your own tailnet, mark the devices you know as healthy, flag the anomaly, and quarantine it.

## What it does

- **Scan.** Lists every device in your tailnet through the official Tailscale API, or, with no credentials, through the local `tailscaled` (read-only, partial view). It does no network scanning: no packets to devices, no port probes.
- **Mark healthy.** `sentry baseline` records the devices you know as known-good. `sentry scan` compares against it and marks matching devices healthy.
- **Flag the anomaly.** 13 rules, each with its own tests. They flag a new device, an unexpected owner, new tags, subnet routes or exit node, a changed OS or addresses, cloned node keys, and key and client hygiene. Exit codes are 0 clean, 1 anomalies and 2 error, so a cron job or Task Scheduler entry can alert. `--json` and `--webhook` are optional.
- **Isolate.** `sentry isolate <device>` replaces the device's tags with `tag:quarantine` and can also `--deauthorize` it. It is a dry run unless you pass `--apply`. It refuses to isolate the machine it runs on, and it writes every action to a hash-chained audit log. `sentry release` undoes it.

## Try it without changing anything

```bash
sentry baseline --source local
sentry scan --source local
```

For the full view, create a **read-only** OAuth client (scope `devices:core:read`) and set `TS_OAUTH_CLIENT_ID` and `TS_OAUTH_CLIENT_SECRET`. Then run `sentry baseline --force` and `sentry scan`. `sentry isolate <device>` without `--apply` prints the exact API calls it would make and changes nothing.

**Before you isolate anything for real, apply the quarantine policy.** Tagging alone blocks nothing: [`examples/quarantine-policy.hujson`](https://github.com/montjeffrey/tailnet-sentry/blob/v0.1.0/examples/quarantine-policy.hujson) is a tailnet policy in which `tag:quarantine` reaches nothing. `--apply` needs a separate client with `devices:core` and `tag:quarantine` selected. See [token scopes](https://github.com/montjeffrey/tailnet-sentry/blob/v0.1.0/README.md#token-scopes).

## Install

1. Download the binary for your platform and `SHA256SUMS`. With the GitHub CLI:
   ```bash
   gh release download v0.1.0 --repo montjeffrey/tailnet-sentry --pattern sentry-windows-amd64.exe --pattern SHA256SUMS
   ```
2. Verify it, from the folder you downloaded to:
   - Linux/macOS: `sha256sum -c SHA256SUMS --ignore-missing`
   - Windows: `Get-FileHash sentry-windows-amd64.exe` and compare with its line in `SHA256SUMS` (the case doesn't matter).
   - Build provenance, which proves the binary was built from this repository by its release workflow:
     `gh attestation verify sentry-windows-amd64.exe --repo montjeffrey/tailnet-sentry`
3. Rename it to `sentry` (or `sentry.exe`) and put it on your `PATH`.

Or build from source with Go 1.26+: `go install github.com/montjeffrey/tailnet-sentry/cmd/sentry@v0.1.0`.

Read [SECURITY.md](https://github.com/montjeffrey/tailnet-sentry/blob/v0.1.0/SECURITY.md) for how credentials and untrusted device data are handled.

## Known limits

- **Binaries are not code-signed yet.** Windows may show "Unknown publisher" or a SmartScreen warning, and Smart App Control may block them. On macOS, clear the quarantine flag with `xattr -d com.apple.quarantine sentry`.
- **The local source sees only part of the tailnet.** Without credentials, sentry sees only the peers your policy shows this device, and it can't see their client versions, pending routes, unapproved devices or cloned keys.
- **A user-owned device can't be fully released through the API.** Tailscale won't remove every tag from a device, so after `release` a device that had no tags before isolation must re-authenticate as its user (`tailscale up --force-reauth` on that device).
- **Tags don't revoke subnet routes.** A quarantined subnet router or exit node can keep forwarding until you `--deauthorize` it or revoke its routes. The isolate plan warns you when this applies.
- **It polls.** A scan sees the tailnet at that moment. Anything that joins and leaves between scans is missed.
